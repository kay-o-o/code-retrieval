# 改造记录

上游 `rasbt/mini-coding-agent`，单文件 1,019 行。在其上做三轮改造，每轮先量一个数、再改、再量。

基线：10 道仓库内任务通过 2 道，失败形态统一为 `Stopped after reaching the step limit without a final answer`。

---

## 一、工具调用：文本协议改原生

上游用 prompt 教模型输出 `<tool>{...}</tool>`，再用正则从回复正文里抓。现代模型走结构化 `tool_calls` 通道，输出里带 `<|DSML|` 系列标记，`parse()` 认不出，判成格式错误后重试到上限。

改法：

- `complete()` 增加 `tools` 参数，把上游的字符串 schema（`"str='.'"`、`"int=1"`）翻译成 JSON Schema；
- `ask()` 优先读 `last_tool_calls`，无结构化调用时退回文本解析。

副作用：文本协议下模型只能输出 `<tool>` 或 `<final>`，收口由格式强制；换成原生调用后可无限调工具，收口责任回到代码侧。实测接完通道仍为 2/10，失败任务的工具序列是 `search, search, run_shell, search...`。

强制收口：工具预算耗尽轮不再传 `tools`，只追加一句 `Tool budget is exhausted. Answer the user now using what you already collected.`。拿掉选项比在 prompt 里劝阻有效。

2/10 → 7/10。

---

## 二、检索：子串匹配改混合检索

剩余失败任务的共同形状是中文提问、英文标识符：

| 提问 | 期望 | 上游 `search` 结果 |
|---|---|---|
| 工具返回内容超过多少字符截断 | `MAX_TOOL_OUTPUT = 4000` | `(no matches)` |
| `read_file` 一次最多读多少行 | `int=200` | `(no matches)` |

上游 `search` 是 `pattern.lower() in line.lower()`，问句里没有这个串就永远 0 命中，模型换词重搜直到步数耗尽。

新增 `code_index.py`，零第三方依赖（`urllib` 发请求、`math` 算余弦）：

- **切块**：按空行切，约 26 行、重叠 6 行。起点从块中点改到 2/3 处——从中间找空行会把函数切碎，答案被挤出 top-3。
- **两路排序**：BM25（英文标识符 + 中文 unigram/bigram）负责符号名，向量（`text-embedding-v3`，1024 维）负责换说法的问句。
- **加权 RRF** 融合。
- **上下文头**：每块补一行 `文件 X › 符号列表` 再向量化。只取块首行不够——带重叠后块首常是上一个函数的尾巴，`read_file` 的 schema 块因此被标成 `def remember`，T06 检索失败；改为列出块内覆盖的全部符号后恢复。
- **定义优先**：提及标识符的块常排在定义它的块之前，对 `def X` / `class X` / `X =` / `"X":` 按出现次数加分。R@1 9.1% → 18.2%，MRR 0.276 → 0.294。

RRF 的 k 与权重按本仓库语料实测：k=10、0.8/0.2 时 R@3 36.4%；k=3、0.5/0.5 时 27.3%。k=60 来自 web 规模语料，146 个块时会把名次压平。

## 三、评测口径

四条，前三条错在尺子，第四条错在被测对象：

| # | 问题 | 修法 |
|---|---|---|
| 1 | 题目内联在评测脚本里，脚本自身被索引且语义与题目一致，BM25 直接排第一 | 题目抽到 `eval/tasks.json`，描述语料的东西放在语料外 |
| 2 | gold 存 `path:line`，源码涨 300 行后行号全错位，脚本静默算错 | 改存锚点字符串（`"def tool_run_shell"`），找不到锚点直接报错退出 |
| 3 | 评测脚本复制了一份 RRF 融合逻辑，未带生产代码的 `_rare_terms` 加分 | 直接调 `index.search()` |
| 4 | `format_hits()` 遇字符预算即 `break`，5 个命中只显示 2 个，top-1 排错时正确答案在 rank 4 也看不到 | 按剩余块数分摊预算，5 块都露头 |

## 四、作答长度

修完检索仍有 1 题失败，形态变了：模型已找到答案，回答在句中截断——`max_new_tokens=512` 不够成段输出。工具调用轮输出短，512 够用；作答轮单独设下限 1024，`finish_reason == "length"` 时翻倍重试一次。

10/10。

## 六、边界

- 10 道题为自出且都在仓库内，100% 只说明同类问题上有效；有说服力的是 20% → 100% 的幅度，不是终值。
- R@3 36.4% 与端到端 100% 不矛盾：agent 多跳，检索指标衡量一次找对，不是最终答对。
- 11 条用例不足以精细调参，k 与权重在同一批用例上选定，有过拟合风险。
- 未测：`run_shell` 的风险分级、`delegate` 在深层任务上的表现、50 文件以上的大仓库。
